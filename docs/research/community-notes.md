## 1. The facts in play

- **Subnet:** SN66, alpha token `conjectures`, "Incentivizing breakthroughs on decades-old open mathematical conjectures" ([SubnetRadar SN66 dossier](https://subnetradar.com/subnet/66)). Registered on chain well before the pivot: [bittensor.ai](https://bittensor.ai/subnets/66) records the slot as registered "1y 5mo ago (Mar 7, 2025)" under owner `5CJCRGep…mGPTjT`.
- **Mechanism:** publish open problems as exact Lean 4 statements; a miner pays a flat fee per submission; the Lean kernel (plus Comparator, plus fourteen gates) decides; a human review then gates payment ([conjectures.io/how-it-works](https://conjectures.io/how-it-works)).
- **Pool:** drawn from Google DeepMind's [`formal-conjectures`](https://github.com/google-deepmind/formal-conjectures). The audited release was **259 targets** — 235 Erdős and 24 of Ben Green's Open Problems ([tasks PR #13, "Publish 259 reviewed targets", 8 Sept 2026](https://github.com/conjectures-io/conjectures-tasks/pull/13); [validator PR #77](https://github.com/conjectures-io/conjectures-validator/pull/77)). After Erdős 96 was reinstated on 10 September the pool became 260 targets / 236 Erdős + 24 Green ([reinstatement decision, 2026-09-10](https://github.com/conjectures-io/conjectures-validator/blob/main/docs/review-decisions/2026-09-10-erdos-96-reinstatement.md)).
- **Results as of 14 Sept 2026:** 24 submissions, 19 Lean-verified, 5 Lean-rejected ([conjectures.io/results](https://conjectures.io/results)). The recent run of accepted proofs is a single solver hotkey, shown as **JenW1N**, on 9–11 September (Erdős 196, Erdős 272-szabo-strong, Green 47, Green 51-one-half, then Erdős 96 and Green 15, then Erdős 944 and Erdős 354-part-i) — same page.
- **Partial awards:** several submissions were paid as `FORMALIZATION_DEFECT_AWARD` rather than for solving the conjecture — the results page reason string is "Defect in the published task" (Erdős 726, paid; Erdős 567-part-i, paid) ([conjectures.io/results](https://conjectures.io/results); rationale in [validator `docs/review-decisions/2026-08-05-erdos-15.md`](https://github.com/conjectures-io/conjectures-validator/blob/main/docs/review-decisions/2026-08-05-erdos-15.md)).
- **Two Green's-open-problem submissions were rejected outright:** Green's open problem 3, twice on 6 Aug 2026, "Already solved before this submission"; Green's open problem 44 on 8 Sept 2026, "Already formalized elsewhere" ([conjectures.io/results](https://conjectures.io/results)).
- **Channel:** the subnet's Discord channel lives inside the official Bittensor Discord — [channel 1531681554420596969, server 799672011265015819](https://discord.com/channels/799672011265015819/1531681554420596969). Every SubnetRadar brief links the individual message IDs it summarised.
- **Fee — a live discrepancy:** the site's own how-it-works page states "**Per attempt 0.25 τ**" and "One transfer of 0.25 τ from your wallet funds exactly one verification attempt" ([conjectures.io/how-it-works](https://conjectures.io/how-it-works)), while the validator repository README says "a miner pays **0.5 TAO**" and "The miner pays exactly 0.5 TAO" ([conjectures-validator README](https://github.com/conjectures-io/conjectures-validator)), and [SubnetAlpha](https://subnetalpha.ai/subnet/conjectures/) repeats "0.5 TAO per submission". The FAQ deliberately defers the number to the submit page: *"The exact price is shown there rather than here, because it is a configuration value and can change"* ([FAQ](https://conjectures.io/faq)). Discord discussion on 20 Aug also records "a proposal to adjust submission fees using subnet alpha tokens" ([SubnetRadar 2026-08-20](https://subnetradar.com/subnet-news/66/2026-08-20)). **RESOLVED:** the live value is `credit_price_rao: 250000000` = **0.25 τ**, read from `GET https://conjectures.io/v1/catalog/meta` and confirmed by `conjectures tasks sync` (both 2026-09-14). So the site's how-it-works page is correct and the validator README and SubnetAlpha are stale. See `docs/04-economics.md` and `docs/research/target-freshness.md` §1 for the raw response.

## 3. What the community has contributed

This is the part with the most substance, and it is mostly on GitHub rather than in chat.

### 3.1 An external contributor found and diagnosed a verifier bug

- On **8 September 2026** a miner reported that a bug in the validator's verifier Docker image "would cause all verifications to fail before reading proofs"; the team acknowledged it and "the fix was implemented" the same day ([SubnetRadar 2026-09-08](https://subnetradar.com/subnet-news/66/2026-09-08)). This is the clearest documented case of a community member materially improving the subnet's infrastructure.
- The brief does not name the fix. [PR #76, "Make the trusted Lean cache readable to the verifier user"](https://github.com/conjectures-io/conjectures-validator/pull/76) (merged 7 Sept 2026) is a plausible match given the symptom ("fail before reading proofs"), but the correspondence is **UNVERIFIED** — the brief does not cite the PR.

### 3.2 A second, deeper bug report — with a correction of its own diagnosis

`asura625` (not a repo member by GitHub association) filed [issue #41](https://github.com/conjectures-io/conjectures-contribution/issues/41): the contribution verifier's 8,192 MB memory cap was believed to be killing certificate-heavy contributions. After a cap raise, the reporter corrected his own theory:

> "Fresh data from run 33498866791 … **this is not a memory limit** … It fails **27 seconds** in, while the same file takes **75 s** and peaks at **7.9 GB** on an identical toolchain locally — so it dies long before it could approach even the old 8 GB cap. `pthread_create` is failing for a reason other than memory: most likely a **pids/nproc cap** on the sandbox."

and, on close: "the binding constraint is thread/process headroom rather than RAM. `LEAN_NUM_THREADS=1` compiles this file cleanly in 78 s…" — the issue was resolved and closed ("Confirmed resolved — PR #40 verified and merged").

This is a community member doing the classifier work on the subnet's own CI, and the thread is now part of the repo's public record.

## 4. Criticism and open concerns (attributed, not adjudicated)

### 4.1 Does open-sourcing solutions destroy the incentive?

The most quoted debate is the 15 August thread (37 messages): "Team discussed the subnet's open-source approach to problem-solving and monetization challenges… **Critics raised concerns about incentive structures and whether miners will remain invested after solving problems, questioning long-term sustainability**" and "**Community debate over whether open-sourcing solutions creates unsustainable incentives**" ([SubnetRadar 2026-08-15](https://subnetradar.com/subnet-news/66/2026-08-15)). The criticisms are attributed by the distiller to "critics"/"community", with no handles — so *who* said it is not recoverable from the public record (see §5).

The team's own design answers the question in the FAQ, in the opposite direction from the critics: "Rewards are paid on a solve only. Someone who works on a problem for three months and does not settle it earns nothing, and that is the intended design rather than an oversight" ([FAQ](https://conjectures.io/faq)). Note that this makes the *criticism* and the *design* the same statement: a solver who publishes a proof has no further reason to hold alpha, and a solver who fails is unpaid. The tension here is between the failure mode critics describe (miners exit after a solve) and the incentive the design provides for them to stay (bounties rise on the remaining pool as solves land — "solving one raises the bounty on everything left").

### 4.2 Bounty and reward-formula churn

- 9 Sept: "Solve-time weighting may favor safe generic work over speculative contributions," and members noted "Homepage still says 'paid on a solve, not on effort' conflicting partial contributions" ([SubnetRadar 2026-09-09](https://subnetradar.com/subnet-news/66/2026-09-09)).
- 11 Sept: "Members discussed low bounties, and the team said they will rework the bounty formula to more evenly reward problems and disincentivize waiting to submit as bounties rise"; the team also confirmed "no retroactive rewards on an already-solved problem" ([SubnetRadar 2026-09-11](https://subnetradar.com/subnet-news/66/2026-09-11)).
- The formula has since changed at least twice in nine days: a 15-day linear ramp to 1/8 plus a defect-award cap ([PR #88, 10 Sept](https://github.com/conjectures-io/conjectures-validator/pull/88)), then a second "new bounty formula… to stabilize pool rewards" ([SubnetRadar 2026-09-12](https://subnetradar.com/subnet-news/66/2026-09-12)). Each change moved the price of an unsolved target under miners who had already committed compute — which is exactly what the 11 Sept complaint about retroactivity was about.

### 4.3 Contribution recognition and the missing appeal clock

See §3.4. Stated plainly by the complainant: contributors are "guessing at the standard" with no signed weights, and the appeal right is unreachable. Issue #65 is open, and the fix it asks for is procedural, not financial: "Publish the intended review cadence — even 'reviews run monthly' or 'at the first payout event'."

### 4.4 Economics, emission, and deregistration risk

- **Third-party read on emission:** SubnetRadar's SN66 dossier states "**Earning ~0% emission**. Under the price-based emission model the chain is not funding this subnet right now — a structural path to deregistration", alongside "Emission Share 0.01% #64 of 77" ([SubnetRadar SN66 dossier](https://subnetradar.com/subnet/66), captured 14 Sept 2026). A different third-party tracker reports "Network share 0.14% #79 by emission" ([bittensor.ai](https://bittensor.ai/subnets/66)) — different metric and different snapshot, so the two are not directly comparable. Both are third-party readings; neither is a primary chain reading.
- **The team has said the same thing in chat:** 11 Aug — "Subnet deregistration risk if issues persist"; 26 Aug — "Subnet nears risk threshold despite 50 new problems added recently", "Team proposes reverting to agent subnet structure for stability", "Miner sentiment indicates declining confidence in current model" ([08-11](https://subnetradar.com/subnet-news/66/2026-08-11), [08-26](https://subnetradar.com/subnet-news/66/2026-08-26)).
- **Structural detail that matters for a miner reading the economics:** the validator's emissions worker directs miner emission to a treasury UID rather than paying per block — "Subnet 66 treasury weight setter (100% to UID 121 every epoch)" ([validator README](https://github.com/conjectures-io/conjectures-validator)), consistent with the FAQ: "Miner emissions accumulate in a treasury rather than being paid out per block" ([FAQ](https://conjectures.io/faq)) and with SubnetAlpha's description of "an emissions worker that submits a single weight per Subnet 66 epoch — directing 100% of emissions to the treasury UID" ([SubnetAlpha](https://subnetalpha.ai/subnet/conjectures/)). That is why the site can advertise bounties in dollars while the subnet's own emission share is microscopic: **the prize pool and the emission are two different money supplies**, and only the pool pays miners.

## 5. The broader context, and why it cuts both ways for a miner

**The validating side.** The subnet's thesis is that mid-2026 is the moment model-assisted search can settle long-open problems, and there is real evidence for it:

- **Two counterexamples in one week of July 2026.** Levent Alpöge's Jacobian-conjecture counterexample in dimension three (open 87 years; "posed 1939"), posted 20 July 2026 with the explicit map and the crediting line "the model Fable" ([X](https://x.com/__alpoge__/status/2079028340955197566); [conjectures.io home](https://conjectures.io/)); and Dmitry Rybin's Dinitz–Garg–Goemans counterexample found with GPT 5.6 Pro on 22 July ([conjectures.io home](https://conjectures.io/)). Epoch AI's own footnote dates the Alpöge presentation to 19 July and names Claude Fable 5 ([Epoch PDF](https://epoch.ai/files/frontiermath-erdos.pdf)) — a one-day and naming discrepancy between sources that is **UNVERIFIED** either way.
- **OpenAI's unit-distance counterexample** (20 May 2026) is the event that made Erdős problems a mainstream capability story ([Quanta](https://www.quantamagazine.org/why-the-legendary-erdos-problems-are-falling-to-ai-20260803/)).
- **DeepMind's formal-proof-search paper:** "Our most capable agent autonomously resolved **9 of 353** open Erdős problems at the per-problem cost of a few hundred dollars, proved 44/492 OEIS conjectures… identified several misformalizations in the literature" — run over *all* the Lean statements then in Formal Conjectures, and logged on Terence Tao's wiki ([arXiv:2605.22763](https://arxiv.org/html/2605.22763v2), cited in [Quanta](https://www.quantamagazine.org/why-the-legendary-erdos-problems-are-falling-to-ai-20260803/)).
- **Epoch AI's FrontierMath Erdős** (announced 1 Sept 2026) turns 68 open problems into a benchmark: "68 problems that are open as of August 2026… selected by the second author [Thomas Bloom] among 652 open problems on erdosproblems.com", 50 of 68 statements "taken from Formal Conjectures", every attempt verified by Comparator in a sandbox ([Epoch](https://epoch.ai/latest/announcing-frontiermath-erdos), [benchmark](https://epoch.ai/benchmarks/frontiermath-erdos)). A third-party account of the first results reports GPT-6 Astra resolving 2 of 68 and "no prior AI system… solved any of these problems" before it ([techjack](https://techjacksolutions.com/ai-brief/epoch-ai-frontiermath-erdos-gpt6-astra-results/), a secondary summary — treat as `UNVERIFIED` until read on Epoch's own results page).
- **Thomas Bloom's own calibration:** Epoch reports Bloom "roughly estimated that something like 3–5 Erdős problems of this caliber had been solved by AI as of August 2026" ([Epoch](https://epoch.ai/latest/announcing-frontiermath-erdos)). Bloom's tracker, [erdosproblems.com](https://www.erdosproblems.com/), is the reference the subnet's own audits cite.

**The double-edged part.** The same context that makes the premise credible makes individual targets un-payable at any moment, and the subnet's own rulebook says so:

1. **The source is shared with the competition.** Formal Conjectures is the pool source and also the statement source for 50 of Epoch's 68 benchmark problems ([Epoch](https://epoch.ai/latest/announcing-frontiermath-erdos)). Any agent pointed at Formal Conjectures — the thing the DeepMind paper did at scale — is walking the same list. The target a miner picks may be being solved, right now, by a lab that will publish whether or not any bounty exists.
2. **Settling elsewhere retires the target with no bounty payable.** Documented cases: Erdős 477 and 536 withdrawn after external solves ([brief](https://subnetradar.com/subnet-news/66/2026-08-19)); Erdős 1199 retired to an arXiv paper ([RETIREMENTS.md](https://github.com/conjectures-io/conjectures-tasks/blob/main/tiers/tier-1/RETIREMENTS.md)); Erdős 126 retired because the tracker records PROVED (LEAN); Green 3 rejected because Franchi–Gowers–Yip (arXiv:2607.06073v1, 7 July 2026) "proves the exact product-free-subset target" — the repo's own note says submissions "were rejected under NOT_NOVEL after substantially implementing that published solution"; Green 44 rejected "Already formalized elsewhere". The site states the admission policy it then enforces: "Anything already settled, or with a resolution in flight, is dropped" ([how-it-works](https://conjectures.io/how-it-works)).
3. **A whole class of forfeited work is structural, not unlucky.** Erdős 15, 567-part-i, 939, Green 42 and Green 77 were retired as `SOURCE_MISMATCH + EXPLOITABLE`: the Lean statement did not mean the informal problem ([RETIREMENTS.md](https://github.com/conjectures-io/conjectures-tasks/blob/main/tiers/tier-1/RETIREMENTS.md)). A miner who reads the Lean statement and the informal problem carefully is spending effort on a target that may pay only the defect award ($750-equivalent in the Erdős 15 case) rather than the bounty. The team does publish this after the fact, and the review-decision README's own audit note says 76 of 137 live targets at that time were "stated through a non-Mathlib definition" — the shape correlated with all three confirmed defects.
4. **Quarantines are conservative and expectant.** Erdős 1059, Erdős 12-iii, Erdős 242, Erdős 727-k-2 and Erdős 96 were quarantined on 8 Sept pending adjudication of prior claims, then Erdős 96 was reinstated on 10 Sept with its 5 Aug bounty age preserved ([RETIREMENTS.md](https://github.com/conjectures-io/conjectures-tasks/blob/main/tiers/tier-1/RETIREMENTS.md), [reinstatement](https://github.com/conjectures-io/conjectures-validator/blob/main/docs/review-decisions/2026-09-10-erdos-96-reinstatement.md)). For a miner this is a two-sided signal: the team will freeze a target on an unverified claim from elsewhere (no work wasted on it, but no work paid either), and it will unfreeze it.

The net for a miner: the context validates that open problems are *attackable*; it does not validate that any particular target stays *payable*. The pool's own audit trail shows both directions — external solves retiring targets before a miner reaches them, and miners reaching targets (Green 29, Green 51, Erdős 96, Green 15, Erdős 196, Erdős 272) that then retire because the subnet paid.
